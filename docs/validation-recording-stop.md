# 녹화 종료 지연 점검 (2026-10-26)

기준: `b6434d1` 이후 로컬 수정. 검증 후 버전을 0.3.12로 올리고 빌드했다. 커밋·태그·스토어 배포는 진행하지 않았다.

## 재현과 수정

- 종료 버튼·단축키가 백그라운드 명령 왕복을 기다리는 동안 인코더가 계속 녹화했다. `node scripts/check-player-input.mjs`에서 메시지 응답을 보류하자 `recording !== inactive`로 실패했다. 녹화 탭의 입력은 해당 탭에서 바로 종료하고, 팝업도 녹화 탭으로 직접 전달한다. 탭 소실 시 기존 백그라운드 복구 경로를 사용한다.
- 종료 이벤트가 늦으면 캔버스 갱신과 녹화용 트랙도 남아 있었다. 공통 종료 함수에서 `stop()` 직후 캡처 자원을 해제한다. 최종 데이터 이벤트와 저장 대기는 유지하고, 중복 `requestData()` 호출은 제거했다.
- 이전 녹화의 늦은 종료 요청이 새 녹화를 완료시키는 경합을 재현했다. 팝업·백그라운드·녹화 탭 사이에 녹화 ID를 전달하고, 다른 녹화에 대한 요청은 무시한다. `node scripts/check-recording-recovery.mjs`의 해당 검사가 수정 전 실패, 수정 후 통과했다.
- 저장을 기다리는 동안 녹화 시간이 계속 증가하지 않도록 방송 화면에 `저장 중`을 표시한다. 실제 캡처 자원은 해제하되 최종 저장 응답 전까지 녹화 담당 상태를 유지한다. 이 순서는 단위 검사에서 수정 전 실패, 수정 후 통과했다.

## 검증 범위

- 빌드와 전체 단위 검사 통과. 정규화, 영역 배치, FFmpeg 해제, 녹화 정리·저장 지연·복구, 화면 이동, 단축키, 분할 계산을 포함한다.
- Chromium 전체 브라우저 검사 8개 통과. 최종 수정에 해당하는 종료 검사도 재실행했다.
- 메시지 전달, 체크포인트 응답, 최종 저장을 따로 지연시키는 실제 WebM/MP4 검사: 전체 녹화 단축키, 영역 녹화 버튼, 팝업 종료를 포함한다. 전체·영역 입력의 같은 이벤트 처리 안에서 인코더가 inactive이고 녹화용 트랙이 모두 ended인지 검사한다.
- 저장 결과의 마지막 구간 탐색과 음성 디코딩을 확인한다. 합성 원본의 오디오 신호가 실제 파일에 남았는지도 검사한다.
- 기존 브라우저 검사는 분할·배속·GIF·프레임 저장, 변환 실패 시 대체 처리, 미니플레이어 이동, 저장 실패 복구, 결과창 중복 방지를 포함한다.
- 최종 지연 검사: Chromium 2개 및 Edge 2개 통과. 각 검사에서 전체·영역·팝업 종료와 체크포인트·최종 저장 지연을 확인했다.
- Chromium 1080p/30fps 전체·영역 녹화 종료 8회 반복: 각 회차의 GC 후 인코더·캔버스 잔존 수 0, 변환 워커 0. 워밍업 이후 JS 힙 증가는 150,172바이트였고, 같은 모드의 이벤트 리스너 수는 증가하지 않았다.
- Edge 시작/취소 16회: 4회 단위 검사에서 인코더·캔버스·변환 워커 잔존 수 0. 종료 시 IndexedDB의 recordings/parts/chunks 모두 0개였다. 취소 경로 검증 뒤 최종 저장 상태 유지 보완을 적용하고 종료 검사를 재실행했다.
- 두 반복 검사 모두 플레이어 원본 캡처는 한 번만 생성됐다. 재사용을 위해 비활성화한 원본 오디오 트랙 1개는 의도적으로 남으며, 녹화용 복제 트랙과 캔버스 트랙은 남지 않았다. 이 수치는 OS/GPU 메모리 누수 부재를 보장하지 않는다.

## 재실행

```powershell
npm run check
npx playwright test extension.spec.mjs -g 'stop releases capture'
$env:CROPCLIP_TEST_BROWSER = 'msedge'
npx playwright test extension.spec.mjs -g 'stop releases capture'
```

반복 녹화 검사는 기존 `recording-profile.spec.mjs`를 사용한다. 생성된 프로파일은 Git에서 제외된 `node_modules/.cache/cropclip-stop-profile-chromium.json` 및 `cropclip-stop-cancel-profile-edge.json`에 저장한다.

## 한계

- 브라우저 메인 스레드가 막혀 입력 이벤트 자체가 전달되지 않는 시간까지 제거하는 수정은 아니다. 입력 처리 후 불필요한 메시지 왕복과 캡처 지속을 제거했다.
- 파일 저장 완료는 남은 데이터와 디스크 처리 속도의 영향을 받는다. 빨라 보이도록 데이터를 버리거나 저장 성공을 먼저 보고하지 않는다.
- 실제 치지직 방송을 여러 시간 재생하면서 다른 확장 프로그램·탭·GPU 부하를 함께 주는 환경은 검증하지 않았다. 합성 영상과 제어된 지연 검사만으로 모든 브라우저·드라이버 누수가 없다고 단정할 수 없다.
